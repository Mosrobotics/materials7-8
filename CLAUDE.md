# materials7-8

Сайт с учебными материалами Mosrobotics на MkDocs Material: https://mosrobotics.github.io/materials7-8/
Подробности для авторов — в README.md.

- `docs/` — страницы сайта (Markdown), `docs/assets/` — картинки и файлы.
- `mkdocs.yml` — настройки и меню (`nav:`): новую страницу обязательно добавить туда.
- `equipment-links.txt` — ссылки на оборудование («Название: ссылка»); хук `hooks/equipment_links.py`
  при сборке подставляет их в таблицы `docs/equipment.md` (незнакомое название — в раздел «Другое»).
  Ссылки в саму таблицу руками не вписывать. Бот CPM_BOT дописывает в этот файл через `/material`.
- `.github/workflows/deploy.yml` — workflow «Публикация сайта»: при push в `main` собирает и выкладывает сайт на GitHub Pages.
- Проверка перед коммитом: `pip install -r requirements.txt` и `mkdocs build --strict` — должно пройти без ошибок и предупреждений.

## Работа в команде (обязательно)

Над проектом работает команда, репозиторий: https://github.com/Mosrobotics/materials7-8 (ветка `main`).

1. **Перед началом работы** — получить свежие изменения: `git pull --rebase --autostash`.
   Это же делает хук в `.claude/settings.json` перед каждым запросом. Если pull сообщил
   об ошибке или конфликте — сначала разобраться с ним, потом менять файлы.
2. **После каждого законченного изменения** — сразу коммит и push:
   `git add <файлы> && git commit -m "<что сделано>" && git push`.
   Сообщение коммита — кратко по-русски, что и зачем изменено.
3. Коммиты — только от имени автора из git config. **Без** строк `Co-Authored-By: Claude`
   и других упоминаний Claude в сообщениях коммитов и PR.
4. Если push отклонён (кто-то успел запушить раньше) — `git pull --rebase`, затем снова `git push`.
   Никогда не делать `push --force` без явной просьбы.

## Нельзя коммитить

`site/` (результат сборки), `.venv/`, `__pycache__/` — уже в `.gitignore`; а также любые токены,
пароли и личные данные учеников. Большие файлы и видео — на Яндекс Диск, на сайт только ссылку.
